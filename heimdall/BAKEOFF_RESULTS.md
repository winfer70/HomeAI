## Failure mode notes (manually verified, not a harness bug)

Blank "Tool called" cells were checked by hand against each model's raw
response `content` field to rule out a parsing bug in the harness:

- **`qwen2.5-coder:7b`** never emits Ollama's native `message.tool_calls`
  field despite `/api/show` listing `tools` as a capability. Instead it
  writes the *correct* tool name/arguments as a JSON string inside
  `message.content` (plain text), e.g.
  `{"name": "control_switch", "arguments": {"entity_id": "switch.0x54ef4410016759d1_up", "state": "on"}}`.
  This disqualifies it for HA's Ollama conversation integration, which reads
  `message.tool_calls`, not free-text content - it would need a fragile
  custom parser to work at all, and still wouldn't get credit under this
  harness's strict native tool_calls check. Coder-tuned models appear to
  prefer describing a function call as code/JSON text rather than using the
  chat API's structured mechanism.
- **`deepseek-r1:8b`** ignores the supplied tool schema entirely - it
  invents its own tool name and shape (e.g. `{"tool": "TurnOnLight", "params": {"light": "main_light"}}`
  wrapped in a markdown code fence) instead of matching `control_switch` /
  `entity_id` from the schema it was given. Combined with very high latency
  (4-36s per prompt vs ~1s for qwen2.5:7b-instruct - consistent with a
  reasoning model's extra thinking overhead even with `<think>` stripped),
  this rules it out for a snappy voice assistant regardless of accuracy.
- **`qwen2.5:7b-instruct`'s 4 misses** were all *near-misses*, not garbled
  output: correct tool name and correct argument shape every time, but wrong
  `entity_id` picked among several plausible options (e.g. picked the
  bedroom TRV instead of the office TRV for "office radiator", picked the
  aquarium heater instead of the correct switch for one write prompt). This
  looks fixable with a better system prompt that explicitly maps
  room/device names to entity IDs (the harness's system prompt is
  intentionally generic) - worth revisiting once the local agent is wired
  into HA, where the real conversation-agent prompt can include this mapping
  explicitly per Task 8's memory/prompt-injection work.
